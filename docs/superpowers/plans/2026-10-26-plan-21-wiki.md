# Plan 21: The wiki

**Goal:** Add a wiki at `/wiki/` that covers every core game system, so a player can look up what to expect — most importantly the **prefix/suffix list by tier**, but also the ores, the market, the uniques, the passive web, the character sheet, the ascendancy tree, achievements, maps, ascension, and the numbers behind each. It must never drift from the game, so its tables are *generated from the same `src/core/` data* the game runs on.

- **A static page, not a route.** The game is a no-backend static site. The wiki is a second Vite entry (`wiki.html` → `wiki.tsx`) built into the same `dist/`, so it ships with the game and works on any static host under `/wiki/`.
- **One source of truth.** The wiki imports the core data directly — `STAT_TIERS`, `MOD_SIDE`, `MOD_WORDS`, `MATERIAL_TABLE`, `MATERIAL_LABELS`, `CRAFT_COST`, `LEGENDARIES`, `PASSIVE_NODES`, `ASCENDANCY_NODES`, `MAP_MOD_TIERS`, `MAP_SPECIALS` — and renders tables from it. When a constant changes, the wiki changes with it; nothing is hand-copied.
- **Read-only.** The wiki has no game state, no save, no store. It shares the theme tokens and fonts for a consistent look.

**Architecture:**

- **Two Vite entries.** `vite.config.ts` gains a Rollup multi-page input (`index.html` and `wiki.html`), or a single `wiki.html` that loads a `src/wiki/main.tsx`. `wiki.html` reuses the same fonts and `theme.css` tokens so the wiki looks like the game.
- **Pure data helpers in `src/wiki/`** (or `src/core/wikiData.ts`, but kept out of the game bundle so the wiki doesn't bloat the app): one function per table, returning plain rows. These are unit-tested against the same invariants the game obeys (e.g. every stat has a side and a `STAT_TIERS` entry).
- **A `WikiApp`** renders the sections with navigation (sticky sidebar on desktop, a collapsible index on phones). Tables are plain HTML with the wiki's own light stylesheet.

**Tech stack:** unchanged. No new dependencies. No schema change (read-only, no save).

**Spec:** main design §1–§5 (the systems to document) and the "wiki covers everything" note; the README's existing system descriptions are the copy seed.

**Builds on:** Plans 15–20 (`dev-ernest`), because the wiki documents the level-100 cap, the reworked web, the new crafting/economy, the character sheet, the expanded ascendancy tree and the achievements — it must be the *last* plan so its content reflects the final state.

**Roadmap:** 15. level cap 100 · 16. the passive-web rework · 17. crafting overhaul and the ore economy · 18. character stats · 19. ascendancy tree expansion · 20. achievements · **21. the wiki** (this plan) · 22. the stats menu · 23. runes · 24. start screen · 25. skill-tree layout · 26. ascendancy-tree rebalance · 27. crafting rebalance · 28. mining animation · 29. ascendancy icons · 30. damage types and resistances · 31. unified equipment · 32. achievement notifications.

## Global Constraints

- Nothing under `src/core/` imports React or touches the DOM. Wiki helpers live under `src/wiki/` (or import core data but never mutate it), so the game bundle is untouched.
- **The wiki is generated, not hand-copied.** No table of tiers, materials, uniques or nodes is typed by hand; each is computed from core data. Hand-written prose is allowed only for explanations, not for numbers.
- **Read-only:** no store, no save, no `GameStore`, no `TabLock`.
- Phones: the wiki is readable at 390 × 844; tables scroll horizontally rather than overflow; the index collapses.
- No new dependencies; the full suite, typecheck and build stay green.
- Git: work on `dev-ernest`; explicit paths; short imperative commits; no attribution; never push.

## Review Focus

1. **Coverage.** Every section in the outline below exists, and the prefix/suffix-by-tier table is complete for all 32 stats (16 mining + 16 battle) × the tiers the game can roll.
2. **No drift.** A test walks `STAT_TIERS` and asserts the wiki's tier rows match `rangeOf`/`tierRange` exactly; likewise for materials, uniques, passives and map mods.
3. **It ships under `/wiki/`.** `npm run build` produces `dist/wiki.html` (and its assets), reachable at `/wiki/`.
4. **It reads well.** Desktop has a sticky index; phones collapse it; tables scroll; fonts and theme match the game.

## Decisions this plan makes (my calls; overrule them in review)

| Topic | Decision |
|---|---|
| Delivery | A second Vite entry `wiki.html` (Rollup `build.rollupOptions.input`), so `/wiki/` is a static page in `dist/`. No client router. |
| Data source | Wiki helpers import from `src/core/` (read-only) and are colocated in `src/wiki/data/` so they stay out of the game bundle. |
| Prefix/suffix table | One table per gear set (mining, battle), grouped by prefix then suffix. Each row: the stat's `MOD_WORDS` name, its side, its `STAT_TIERS` base/step, and the value range for each tier 1..10 (computed from `rangeOf`). A short note that the rollable tier is capped by the item's level (`tierCap`). |
| Tier listing | Show tiers 1–10 by default with a "higher tiers" note, since `tierCap` is unbounded by depth; the table notes that deeper items roll higher tiers and that lower tiers stay likeliest (`tierWeights`). |
| Material table | `MATERIAL_TABLE` with `from` depth, weight, amount, plus the new ore economy: conversion recipes, exchange rates, and the premium mechanic (Plan 17). |
| Unique/passive/map tables | Generated from `LEGENDARIES`, `PASSIVE_NODES` (grouped: keystones, notables, smalls), `ASCENDANCY_NODES`, `MAP_MOD_TIERS`, `MAP_SPECIALS`. |
| Look | Reuse `theme.css` tokens (fonts, colours, ink/bone/gold) with a dedicated `wiki.css`; no `GameStore` or atlas. |

## Wiki outline (the "cover everything" checklist)

1. **Getting started** — what the game is, controls, Pause, the click/drag/right-click/Alt/Ctrl/Shift actions.
2. **Digging and the mine** — how Gold/Diamonds/materials are earned, bands, veins, hazards, the minimap, the dig-face.
3. **Gear** — slots (mining/battle), rarities, sockets and gems, the paper doll, the stash and its tabs.
4. **Character stats** — the character sheet: DPS, damage range, life, armor, resistances, dig power and dig speed, and how local vs global mods apply.
5. **Prefixes and suffixes** — the centrepiece: the two by-tier tables, how tiers work, how an item's level caps its tiers.
6. **Item levels and tiers** — `tierCap`, `tierWeights`, `baseName`, the magic/rare naming words.
7. **Crafting and enchanting** — every ore craft, the essences/orbs, targeted add/reroll/remove, tempering, Void crystal, Souls upgrade, and map enchanting.
8. **Ores and the market** — the ore table by depth, ore→essence recipes, ore→ore exchange, the decaying premium.
9. **Uniques** — the eight legendaries and their lines.
10. **Maps and dungeons** — map tiers, rarity, modifiers, specials, running, auto-mapping, the log.
11. **Skills** — the passive web: keystones, notables, smalls, how allocation/refund/reset work.
12. **Ascension and the ascendancy tree** — what ascends, the ascendancy points formula (depth + level bonus), the multi-point mid/big nodes.
13. **Achievements** — the families, the ~1000 achievements, and the permanent +0.5%-per-achievement global boost.
14. **Merchant** — Brannoc, Mirela, and the Refiner (what each sells/gambles/trades).
15. **Log, saves, settings and seeds** — the drop/death log, export/import, new world, motion settings, loot filter.
16. **Numbers reference** — a compact glossary of the key constants (bag size, caps, XP curve, offline cap) for players who want the exact figures.

## File structure

```

wiki.html               NEW  the /wiki/ entry (fonts, root div, wiki.tsx)
index.html              MOD  add a "Wiki" link in the header (if desired)
src/wiki/
  main.tsx              NEW  renders <WikiApp>
  WikiApp.tsx           NEW  the section layout and navigation
  wiki.css              NEW  wiki styles, reusing theme tokens
  data/
    affixes.ts          NEW  prefix/suffix-by-tier tables (from STAT_TIERS/MOD_SIDE/MOD_WORDS)
    materials.ts        NEW  ore table, recipes, exchange (from MATERIAL_TABLE + Plan 17 constants)
    uniques.ts          NEW  the legendaries (from LEGENDARIES)
    skills.ts           NEW  keystones/notables/smalls + ascendancy (from the node tables)
    maps.ts             NEW  map mods and specials (from MAP_MOD_TIERS/MAP_SPECIALS)
    achievements.ts     NEW  the achievement families (from ACHIEVEMENTS)
    stats.ts            NEW  the character-sheet rows (from deriveCharacterSheet/deriveStats)
tests/
  wiki/affixes.test.ts   NEW  the tier tables match tierRange exactly
  wiki/data.test.ts      NEW  materials/uniques/skills/maps/achievements/stats match core data
```
